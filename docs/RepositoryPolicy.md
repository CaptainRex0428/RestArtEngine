# 仓库内容与提交约定

公开仓库保存可独立使用的引擎源码、Shader、必要资源、示例工程、构建配置、测试工具、许可证，以及面向使用者和贡献者的技术文档。克隆后的构建与使用不应依赖任何个人协作配置或写作资料。

## 内容归属

| 内容 | 处理方式 |
| --- | --- |
| `include/`、`src/`、`app/`、`Shaders/`、`tests/` | 公开维护，引擎接口、实现与测试。 |
| `Projects/`、`assets/` | 公开维护示例场景、材质、网格及引擎必要资源；提交前检查示例改动是否属于本次任务。 |
| CMake / Premake 配置、`scripts/`、`vendor/` | 公开维护构建、验证和依赖说明；保留第三方版本与许可证。 |
| `README.md`、`docs/` 中列入白名单的文档 | 公开维护操作说明、格式、架构、设计约束、平台边界和可复现验证方法。 |
| AI 角色、技能、提示词、聊天记录和本机协作入口 | 只保留本地，不属于引擎发行内容。 |
| 开发日志、文章、写作规范、底稿、进度交接、源码阅读笔记及配图／动图 | 只保留本地或仓库外的内容目录，不提交。 |
| 构建输出、个人 IDE 状态、布局／主题／GC 偏好、测试日志和截图 | 只保留本地；共享 IDE 配置仅保留不含个人路径的少量明确例外。 |
| 凭据、本机环境配置、个人绝对路径 | 不提交；配置说明使用占位值或可移植示例。 |

## 配置保存在哪里

| 配置 | 位置与用途 | 提交／分发规则 |
| --- | --- | --- |
| 共享构建配置 | 引擎根目录的 `CMakeLists.txt`、`CMakePresets.json`、Premake `.lua` 文件 | 可以提交，使用相对路径或环境变量；不写个人 SDK 安装路径。 |
| 个人构建覆盖 | 本地 `CMakeUserPresets.json`、`*.local.*`、环境文件 | 不提交；可公开不含真实凭据和个人路径的 `.env.example`／`.env.sample`。 |
| 引擎身份 | 引擎根目录 `Engine.raeengine` | 可以提交／随发行版提供，标识引擎版本与构建。 |
| 工程配置与资产 | 各工程的 `.raproject`、`Content/`、`Shaders/` | 公开示例可以提交；个人工程单独管理，不自动加入引擎库。 |
| 引擎安装注册表 | Windows 的 `%LOCALAPPDATA%\RAEngine\engines.json` | 本机安装路径映射，不提交、不随工程打包；换机重新登记。 |
| 编辑器偏好 | 默认在进程工作目录的 `RestArtEngine.imgui.ini`、`RestArtEngine.theme.ini`、`RestArtEngine.gc.json` 等；GC 可通过 `--gc-settings` 指定路径 | 不提交、不当作工程配置；需要迁移时单独处理。 |
| IDE 状态与辅助资源 | 项目的 `.idea/` 等 IDE 目录 | 本机生成物不提交；仅保留忽略规则明确允许的共享配置，不将 IDE 图标混入引擎资源。 |
| 开发协作与写作配置 | 被忽略的本地工作区资料、个人工具配置目录、仓库外内容目录 | 不进入引擎源码仓库或发行包；具体机器路径只记录在本地位置索引。 |

引擎源码根、用户工程根和进程工作目录是不同概念，不能假设编辑器偏好总在源码根。配置内容与解析规则分别见 [工程管理](ProjectManagement.md)、[编辑器指南](EditorGuide.md) 和 [GC](GarbageCollection.md)。

## 文档同步职责

引擎行为、格式或配置发生变化时，更新对应公开领域文档；目录、提交或分发边界变化时，更新本页及 `.gitignore`。本机工作安排、阅读记录、验证历史和写作进度更新各自的本地记录，公开文档不引用这些记录作为使用前提。新增文件先确定归属，再选路径，不能仅因位于 `docs/` 或名为“配置”就认定可以提交。

## 新增文档与资源

`docs/` 使用 `.gitignore` 中的白名单。新增公开文档时，先确认内容是可复用的引擎说明，再同时增加文件和对应忽略例外。领域文档描述当前行为、技术原因、接口约定和限制；日期流水账、某次聊天结论及个人验证产物保存在本地记录中。

公开文档只能依赖仓库内已跟踪文件或公开来源；本地文件即使存在，也不能作为公开文档的链接目标。源码阅读中提炼出的通用设计说明可以写入领域文档，私人阅读过程和协作提示不随之发布。

保留网格 `.obj` 与引擎图片资源的正常跟踪，不能用全局忽略图片、视频或所有 `.obj` 的方式清理日志。文章素材放在仓库外；临时验证输出使用已忽略的 `artifacts/`、`screenshots/` 等目录，不混入引擎资源。

## 提交检查

```powershell
git status --short
git diff --cached --name-status
git diff --cached --check
git ls-files
git check-ignore -v --no-index -- <待检查路径>
```

使用明确文件路径暂存本次改动，核对暂存区而非只检查工作区。不要强制添加本地协作或写作资料。新增工具和文档时同步检查忽略规则，避免换一种命名后重新进入仓库。

`.gitignore` 只影响未跟踪文件，不能阻止已跟踪文件继续提交。已误跟踪的本地资料需在保留工作区文件的前提下，通过 `git rm --cached -- <明确路径>` 移出索引。删除提交只影响之后的版本，历史提交、远端分支、标签及其他克隆仍可能保留旧内容；历史清理须单独评估所有引用和协作影响，不将忽略规则视为历史擦除。

## 打包与换机

Git 提交、源码归档、运行时发行包、个人备份是不同交付物。`.gitignore` 不过滤手工复制、压缩或上传：不要将包含本地资料的整个工作目录直接打包。源码归档从已检查的提交导出；运行时发行包按 [引擎分发](EngineDistribution.md) 的运行文件清单组装，最后检查实际包内文件。忽略的构建产物可以属于运行时发行包，不能因此重新提交进源码库。

Git 克隆只恢复已提交内容，不恢复本地技能、进度记录、个人偏好或外部文章目录。个人资料如需换机，使用单独的私有备份；模型／服务凭据通过工具自己的安全配置方式重新设置，不夹带进项目备份、公开文档或文章。忽略不等于备份，旧机器上的绝对路径也不能直接视为新机器可用路径。
